# MinCifri Trust

**[⬇️ Скачать установщик](https://github.com/miggra/min-cifri-trust/releases/latest)**

Небольшое приложение для Windows: одной кнопкой **включает** или **выключает** доверие к сертификатам НУЦ Минцифры (Russian Trusted Root / Sub CA).

Работает в системном трее.

### Куда именно ставятся сертификаты

В Windows есть два основных расположения хранилищ сертификатов CryptoAPI / Cert:

| Расположение | Что это | Кому действует |
|---|---|---|
| **Current User** (`StoreLocation.CurrentUser`) | Хранилище **текущего пользователя** | Только этому аккаунту Windows |
| **Local Machine** (`StoreLocation.LocalMachine`) | Хранилище **компьютера** | Всем пользователям и большинству служб на этой машине |

MinCifri Trust пишет в **Local Machine**:

- корневой CA → `LocalMachine\Root`  
(оснастка: «Доверенные корневые центры сертификации» на уровне компьютера);
- выпускающий CA → `LocalMachine\CertificateAuthority`  
(оснастка: «Промежуточные центры сертификации» на уровне компьютера).

Посмотреть руками установленные сертификаты можно следующим образом: `Win + R` → `certlm.msc` (хранилище компьютера) или `certmgr.msc` (хранилище пользователя).

## Зачем это нужно

Часть российских сайтов (госуслуги, банки и др.) использует TLS-сертификаты, выпущенные Национальным удостоверяющим центром Минцифры. В Chrome, Edge, Firefox и в Windows они по умолчанию **не доверенные**, поэтому браузер показывает предупреждение о безопасности.

Обычная инструкция — установить корневой и выпускающий сертификаты **навсегда**. MinCifri Trust даёт другой подход: доверие можно **временно включить**, когда сайт нужен, и **сразу выключить**, когда закончили.

## В чём преимущество

| Постоянная установка вручную | MinCifri Trust |
|---|---|
| Сертификаты всегда в системе | Вкл только когда нужно |
| Легко забыть удалить | Выкл одной кнопкой / из трея |
| Расширенное доверие круглосуточно | Окно риска можно сузить по времени |

То есть программа не «обходит безопасность», а помогает **не держать** корневой сертификат Минцифры включённым постоянно, если вы им пользуетесь лишь иногда.

## Риски доверия корневым сертификатам

Любой корневой удостоверяющий центр (CA) в хранилище «Доверенные корневые…» — и предустановленный производителем/ОС, и добавленный вручную — это не «разрешение на один сайт». Это правило: **доверять любой** корректной цепочке, которая заканчивается на этом корне. Браузер и система при этом не показывают привычное красное предупреждение.

Отсюда общие риски модели доверия к CA:

1. **Широкая зона доверия.** Доверяют не отдельному домену, а инфраструктуре выпуска сертификатов конкретного УЦ. Все сертификаты, которые он (или его промежуточные) выпустит по правилам цепочки, будут выглядеть «нормальными».
2. **Компрометация или злоупотребление ключами УЦ.** Если закрытый ключ корня или выпускающего центра окажется у злоумышленника либо будет использован вопреки ожиданиям владельца устройства, можно выпустить сертификат на произвольный домен — и клиенты с этим корнем в доверенных примут его.
3. **Слабый сигнал тревоги.** Пока корень считается доверенным, классическое предупреждение «сертификат не доверен» для таких цепочек не срабатывает; подмену или нежелательный УЦ сложнее заметить «на глаз».
4. **Область действия шире браузера.** Системное хранилище Windows используют не только браузеры: почта, VPN-клиенты, обновления, корпоративный софт и другие программы тоже могут опираться на те же корни.
5. **Предустановленные корни — тот же класс риска.** Набор корней в ОС и браузере уже большой: ими управляют вендоры через программы доверия (root programs). Дополнительный корень, который пользователь ставит сам, просто **ещё больше** расширяет эту зону — на тех же принципах, что и уже лежащие в системе.

Сами по себе корневые сертификаты — штатный механизм HTTPS, а не «вредонос». Риск возникает, когда зона доверия шире, чем нужно для конкретной задачи, и когда лишний корень держится **включённым постоянно**.

Поэтому для сертификатов, которые нужны лишь иногда, разумная практика: включить → выполнить работу → выключить. MinCifri Trust упрощает именно этот режим.

## Как пользоваться

1. Скачайте установщик из [Releases](../../releases) (файл `MinCifriTrust-Setup-*.exe`), не исходники.
2. Установите. При желании отметьте автозапуск при входе в Windows.
3. В окне или в меню трея: **Включить** / **Выключить**.
4. Крестик окна скрывает программу в трей; полный выход — **Закрыть** в меню иконки в трее.

При включении приложение скачивает официальные `.cer` с `gu-st.ru`, проверяет отпечаток корневого сертификата и импортирует их в **хранилище компьютера** (см. выше):

- корневой → `LocalMachine\Root`;
- выпускающий → `LocalMachine\CertificateAuthority`.

Выключение удаляет их из этих же хранилищ по отпечатку (thumbprint).

## Сборка у себя

Нужны .NET 8 SDK и [Inno Setup 6](https://jrsoftware.org/isinfo.php).

```powershell
.\build-release.ps1
```

Результат:

- установщик: `artifacts\installer\MinCifriTrust-Setup-1.0.0.exe`
- portable: `artifacts\publish\MinCifriTrust.exe`

## Ограничения

- Только Windows x64.
- Не настраивает отдельное хранилище Firefox (у него своё).
- Не является средством анонимизации и не связано с VPN — только управление доверием к сертификатам НУЦ Минцифры.
